# Glossary

This glossary describes the behavior implemented in this repository today. It is the shared vocabulary for the code, API, and documentation; it is not a product specification.

| Term | Definition |
|---|---|
| **Corpus** | The Markdown files available to the service from its configured documentation directory after include and exclude filters are applied. |
| **Indexed document** | One Markdown file loaded from the corpus. A document keeps its relative path, title, tags, and full text. |
| **Runbook** | An operational document that describes symptoms, investigation checks, or a typical fix. A runbook is source material, not an instruction generated by the service. |
| **Chunk** | A segment of an indexed document used for retrieval. A chunk retains the original document's path and title so results can point back to the source file. |
| **Question** | The infrastructure-related text submitted to `/query` for retrieval. |
| **Lexical retrieval** | Ranking chunks by shared terms with the question, using token overlap or BM25. It is not semantic or vector search. |
| **Token-overlap baseline** | The original retriever, ranking by matching tokens with smaller bonuses for title, path, and available tags. It is the reference for measuring changes. |
| **BM25** | A lexical ranking method that accounts for term rarity, repetition, and chunk length. It is an alternative to the token-overlap baseline, not a semantic retriever. |
| **Retrieval score** | A ranking value used to order matching chunks within one retrieval method. It is not a probability, confidence level, or measure that a result is correct; scores from different methods are not comparable. |
| **Source** | A returned result identifying an indexed document by path and title, with a matching snippet and retrieval score. |
| **Evidence** | The API's `evidence` entries, which summarize returned results as title, path, and score. They identify retrieved material; they are not independent verification or proof. |
| **Summary** | A short description of the highest-ranked runbook and the number of returned sources. It is assembled by the service, not generated or synthesized by an LLM. |
| **Recommended actions** | The API's `recommended_actions`: up to three actions extracted from the top document's `Checks` and `Typical fix` sections. If those sections provide none, generic fallback actions are returned; these are not necessarily evidence-based. |
| **Index** | The searchable collection of documents, chunks, and any term statistics used for retrieval. It is not a vector index. |
| **Reindex** | Reloading documents from the configured directory and rebuilding the in-memory index without restarting the service. Existing folder filters remain in effect. |
| **RAG (Retrieval-Augmented Generation)** | An architecture that combines retrieval with generated responses. This project name uses “RAG”, but the current service implements lexical retrieval only; it does not generate responses. |
| **Evaluation query** | A benchmark question with a language, query group, split, and judged relevant source paths. An empty relevance set denotes a question the corpus cannot answer. |
| **Query family** | Related evaluation questions about one intent, including translations and paraphrases. A family belongs to only one split to reduce evaluation leakage. |
| **Dev split** | Evaluation queries used to compare alternatives and choose settings. |
| **Held-out test split** | Separate query families used to evaluate a configuration after its settings are frozen. |
| **No-answer query** | A question whose requested information is absent from the evaluation corpus, even if some documents share its words. Returning sources for it is a retrieval false positive. |

## Terms to avoid

- **“Vector search”** or **“semantic search”** for the current retrieval implementation; use **lexical retrieval**.
- **“Confidence”** for a retrieval score; the score is only a heuristic rank.
- **“AI-generated answer”** or **“LLM summary”** for the `/query` summary or evidence; neither is generated by an LLM.
- **“Recommended actions”** as a promise of validated or personalized guidance; the actions are extracted from a source or supplied as generic fallbacks.
- **“Document”** when referring specifically to a retrieved text segment; use **chunk**.
